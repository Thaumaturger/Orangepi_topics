閱讀範圍：node1 `~/llama.cpp`（commit `330f0189c`）的 `src/models/gemma4.cpp`、`src/llama-graph.cpp`、`src/llama-model.cpp`、`src/llama-model-loader.cpp`、`src/llama-kv-cache-iswa.cpp`、`src/llama-context.cpp`，以及 31B GGUF 的 metadata 和 tensor 清單（用自寫的 `~/gguf_meta.py` 讀取，只讀標頭）。

## 1. 31B 模型的架構事實【原始碼／metadata 確認】

| 項目 | 值 | 對切層的影響 |
| --- | --- | --- |
| 層數 | 60 | — |
| `shared_kv_layers` | 0 | **有利**：沒有層會借用其他層的 KV，各段的 KV 完全獨立 |
| `embedding_length_per_layer_input` | 0 | **有利**：沒有 Per-Layer Embedding，後段不需要 token ID |
| 滑動視窗模式 | 每 6 層第 6 層為完整注意力（第 5、11、…、59 層），視窗 1024 | 用絕對層號查表，切層後仍正確 |
| KV head 數 | SWA 層 16、完整層 4；head 維度 256 / 512 | 同上，用絕對層號查表 |
| Embedding | `token_embd.weight` 為 Q8_0，262144 × 5376，約 1.5 GB | — |
| LM Head | **沒有獨立的 `output.weight`，與 `token_embd` 共用** | 第一段（查表）和最後一段（LM Head）都要載入這 1.5 GB |
| 輸入縮放 | token 輸入乘 `sqrt(5376)` | `build_inp_embd` **只縮放 token 列，直接輸入的 `embd` 不縮放**（`llama-graph.cpp` 約 2815 行），後段可直接接前段的隱藏狀態 |
| 每層輸出縮放 | `blk.N.layer_output_scale` | 屬於該層權重，跟著層走 |
| Logit softcapping | 30.0 | 只在最後一段 |
| `rope_freqs` | 全域一份（256 維，給完整注意力層用） | 很小，每段都載入 |

## 2. llama.cpp 現況【原始碼確認】
- **沒有現成的「只跑第 a 到 b 層」功能**。`common/arg.cpp` 只有 control vector 的 layer range，與此無關。
- **Gemma 4 的計算圖**（`gemma4.cpp`）：`for (il = 0; il < n_layer; ++il)` 迴圈，前面用 `build_inp_embd(tok_embd, sqrt(n_embd))` 產生輸入，後面接 `output_norm`、LM Head、softcapping。
- **loader 已支援部分載入**：`done_getting_tensors(bool partial)` 在 `partial=true` 時，允許建立的 tensor 少於檔案內的數量，只印警告（`llama-model-loader.cpp:1405`）。沒建立的 tensor 不會被載入，所以**記憶體只花在該段的層**。
- **KV cache 支援層過濾**：`llama_kv_cache_iswa` 的建構子接受 `layer_filter_cb`，並同時套用到完整層與 SWA 層的子 cache（`llama-kv-cache-iswa.cpp` 約 48–62 行）。MTP 功能已經在用這個機制，可以只為該段的層配置 KV。
- **輸出端支援沒有 logits 的圖**：`llama-context.cpp` 在 `t_logits` 為空時會跳過 logits 複製（約 1846 行），也有 `graph_has_logits` 旗標。中間段可以只輸出 `t_embd`（隱藏狀態）。

## 3. 實作方案：在 llama.cpp 內加「層範圍」參數（同一個 GGUF 檔）

| # | 改動 | 位置 | 估計行數 |
| --- | --- | --- | --- |
| 1 | `llama_model_params` 新增 `layer_start`、`layer_end`（預設 0 / -1 代表完整模型）；common 加 `--layer-range A B` | `include/llama.h`、`src/llama-model.cpp`、`common/arg.cpp`、`common/common.{h,cpp}` | ~40 |
| 2 | 載入：Gemma 4 只建立範圍內的層。`token_embd` 只在第一段或最後一段建立；`output_norm` 只在最後一段建立。有設範圍時呼叫 `done_getting_tensors(true)` | `src/models/gemma4.cpp`、`src/llama-model.cpp` | ~40 |
| 3 | KV cache：Gemma 4 的 iSWA cache 傳入 `il ∈ [a, b)` 的 filter | `src/llama-model.cpp` 的 `create_memory` | ~15 |
| 4 | 計算圖：迴圈改成 `il = a .. b-1`。`a > 0` 時改用只接受 `embd` 的輸入（不建立 `get_rows(tok_embd)`，否則 `tok_embd` 為空會當掉）。`b < 60` 時把 `inpL`（`output_norm` 之前）設為 `t_embd`，不建 LM Head | `src/models/gemma4.cpp`，可能加一個 `build_inp_embd_raw()` 到 `llama-graph.{h,cpp}` | ~60 |
| 5 | 驗證工具 `llama-stage-test`：完整模型跑一段 prompt 存 logits →（重新載入）前段 0..a 輸出所有 token 的隱藏狀態 → 後段 a..60 以 `embd` 輸入 → 比對 logits，再貪婪生成 N 個 token 比對序列 | `tools/stage-test/`（新） | ~250 |

**驗證標準**（對應 9.2 的 W2 Go/No-Go）：
- 兩段串接與完整模型比較：logits 最大絕對誤差 < 1e-3、top-1 token 100% 一致、貪婪生成前 64 個 token 完全相同。
- 運算的順序和種類都相同，預期幾乎完全一致。若有差異，可能來自執行緒歸約順序【推測】。

**單板就能驗證**：前段加後段的記憶體等於完整模型（約 17 GB），所以兩段放在 node1 同一個程序裡串接即可，不需要等其他板子和交換器。Baseline 先跑完整模型存檔，再載入兩段，避免同時佔兩份記憶體。

## 5. 已知風險【推測，實作時驗證】
1. **未載入的層**：`layers[il]` 的 tensor 是空指標，其他程式（`print_info`、記憶體估算、repack、MTP/nextn 路徑）可能有假設所有層都存在的迴圈。需要逐一找出並加範圍判斷。
2. **輸入選擇**：`build_inp_embd` 為了支援混合批次，會同時建 token 與 embd 兩條路徑再選擇。第一段以後必須改寫成只有 embd 路徑。
3. **計算圖重用**：`can_reuse` 等快取邏輯在 embd 輸入下的行為要確認。
4. **輸出列數**：中間段必須輸出所有 token 的隱藏狀態，因為下一段的 prefill 需要每個位置。所以呼叫端要把 batch 的 `logits` 旗標全部設為 1。要確認 `inp_out_ids` 不會把列裁掉。
5. **儲存空間**：此方案每張板子都要有完整的 GGUF（17 GB）。node1 只剩 7.3 GB 可用，其他板子未知。若空間不夠，後續可以再做「每段一個 GGUF」的切檔工具（要重排層號並切 metadata 陣列，較容易出錯，所以排在後面）。

## 6. 對非對稱切層（企劃書 4.2）的新資訊
- 第一段和最後一段都要放 1.5 GB 的 `token_embd`（Q8_0），而且最後一段還要配置 `[B, 262144]` 的 float logits 暫存（每個 token 1 MB）。
- 每層權重約 (17 − 1.5) / 60 ≈ 0.26 GB。首尾各少分約 5–6 層，剛好可以抵消 embedding 的 1.5 GB【推算】。
