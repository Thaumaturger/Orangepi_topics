# 長對話（每人約 4K token）下的吞吐量：資料平行 vs 管線（31B）

**結論：**
1. **在相同的 KV 存放方式下，長對話的吞吐量也大致持平。** 每人 4K token、共用同一段 KV 時，8 人：資料平行 10.40、管線 9.84 t/s（資料平行高 6%）。
2. **管線的優勢仍是人數。** 每人有各自 4K 對話時，資料平行每板最多 4 人（共 8 人），而且已經擠到記憶體極限（node2 可用記憶體一度歸零、node1 開始用 swap 被停止）；管線 16 人時前段仍有 4.3 GB、後段 7.5 GB 可用。
3. **長對話會讓吞吐明顯下降**：資料平行每板 4 人從 7.90（短對話）降到 5.20（共用 KV）或 3.34 t/s（各自 KV）；管線 8 人從 14.79 降到 9.84 t/s。
4. **KV 的存放方式影響很大**：同樣 4 人、4K，各自一份 KV（3.34 t/s）比共用一份（5.20 t/s）慢 36%。管線目前只量了共用 KV，**各自 KV 下的管線吞吐尚未實測**。

## 量測條件
- 時間：2026-11-18 09:51–11:15 UTC（node2 時鐘不準，log 顯示 11/10）
- 兩板 `performance`、8 大核、`-lm dio`；llama.cpp `330f0189c`
- 每人上下文：4,000 token 的共同開頭 + 生成 32 token（管線另有 29 token 的對話格式 prompt）
- 每個組態 1 次
- 指令：
  ```
  # 資料平行，各自 KV（兩板同時；node1 被監控程式停止，只採用 node2）
  taskset -c 0,1,6-11 ./build-cpu-opt/bin/llama-batched-bench -m models/gemma-4-31B-it-Q4_0.gguf \
    -c 16384 -npp 4000 -ntg 32 -npl 1,4 -pps -lm dio -t 8
  # 資料平行，共用 KV（node2 單獨）
  taskset -c 0,1,6-11 ./build-cpu-opt/bin/llama-batched-bench -m models/gemma-4-31B-it-Q4_0.gguf \
    -c 4352 -npp 4000 -ntg 32 -npl 1,4,8 -pps -kvu -lm dio -t 8
  # 管線，切在第 33 層，共用 KV（新增的 --prefix）
  taskset -c 0,1,6-11 ~/llama.cpp-pp/build-pp/bin/llama-pp-stage --role last  -m ... -s 33 -N 60 --listen 192.168.137.31:9000 --n-seq 16 --ctx-seq 4096 -t 8
  taskset -c 0,1,6-11 ~/llama.cpp-pp/build-pp/bin/llama-pp-stage --role first -m ... -s 33 --next 192.168.137.31:9000 --ref /tmp/stage_ref_31b.bin \
    --n-seq 16 --ctx-seq 4096 --prefix 4000 -n 32 -t 8 --configs 1x1,8x2,16x2
  ```
- `-pps`：prompt 只算一次再複製給每個序列。不加 `-kvu` 時，每個序列在自己的 KV 區有一份完整副本（等同各自的 4K 對話）；加 `-kvu` 時，所有序列共用同一段 KV 格子
- `llama-pp-stage --prefix`：開頭灌進序列 0 後，前後兩段都用 `llama_memory_seq_cp` 共用給其他序列（等同 `-pps -kvu`）。pp-stage 也改為 `swa_full = false`（與 llama-server 預設相同）
- 管線開頭的 61 列驗證仍與單板逐位元相同（PASS）
- 原始記錄（`results/raw/`）：`dp4k_node2_1110_2009.*`（各自 KV）、`dp4k_node1_1118_0951.*`（被停止）、`dp4k_kvu_1110_2100.*`（共用 KV）、`pp4k_first_1118_1015.*`、`pp4k_last_1110_2033.*`

## 解讀
1. **同樣的 KV 方式下吞吐持平**：8 人時資料平行（共用 KV）10.40 vs 管線 9.84 t/s，與短對話的結論一致（`6.11`：±6%）。單人時兩者也相同（1.84 vs 1.83）。
2. **共用 KV 會高估速度**：所有人讀同一段 KV，資料重複利用；實際上每個人的對話不同，KV 各自一份，單板 4 人慢了 36%。所以：
   - 資料平行在實際長對話下的數字是 6.68 t/s（8 人，而且記憶體已到極限）。
   - 管線在實際長對話（各自 KV）下的數字**還沒量**，預期也會比 11.33 低。若照資料平行的比例（0.64）推算，16 人約 7.3 t/s【推算】，仍略高於資料平行 8 人的 6.68 t/s，但同時服務 2 倍人數。
3. **對專題論點的意義**：
   - 吞吐量不是管線的優勢（短、長對話都大致持平）。
   - 管線的價值在**相同硬體下能服務的人數多 2–3 倍**，而且總吞吐不輸資料平行；每人的速度則較低（16 人時每人約 0.7 t/s）。
4. **管線的實作限制**：目前前段用 unified KV（為了避免批次被拆開，見 `6.8`）。在各自 KV 的情況下，unified KV 的注意力要掃過所有人的 KV 格子（被遮罩的格子會跳過，但仍要逐格檢查），長對話、多人時可能比資料平行的獨立 KV 區更慢。要實測，需要把每個序列各自填到 4K（prefill 約 16 × 4 分鐘），或改寫前段的批次方式。

## 下一步
