# 重複量測與標準差：管線 vs 資料平行（31B）

**結論：**
1. **量測非常穩定**：同一次載入內重複 3 次，管線與資料平行的總吞吐標準差都 ≤ 0.006 t/s（≤ 0.06%）。兩板跑同一個工作時，速度差 ≤ 0.01 t/s。
2. **不同天、不同次載入之間也只差 0.25%**：管線 32x2 三天的結果為 24.88、24.76、24.79 t/s（平均 24.81，標準差 0.06）。資料平行與 `6.11` 相差 ≤ 0.1%。
3. **所以先前比較中 ≥ 1% 的差距都是真實的差異**，不是量測雜訊。例如短對話 16 人管線比資料平行快 1.9%、32 人快 0.6%：差距很小，但量得出來。
4. **短對話時兩者仍然持平**：16 人 18.49 vs 18.15 t/s、32 人 24.79 vs 24.64 t/s。

## 量測條件
- 時間：2026-11-19（node1 log 顯示 11/18 22:04 – 11/19 01:11，node2 顯示 11/11，兩板時鐘都不準）
- 兩板 `performance`、8 大核、`-t 8`；llama.cpp `330f0189c`（資料平行用 `build-cpu-opt`；管線用 `pp-layer-range` 的 `build-pp`）
- 管線：切在第 33 層，f16 KV，unified；每人 prompt 29 token + 生成 32 token
- 資料平行：兩板同時跑 `llama-batched-bench`，每人 prompt 128 token + 生成 32 token；`-npl` 的第一個 `1` 為暖機
- 長對話：q8_0 KV，每人各自 4,000 token 開頭（`--distinct`），見 `6.13`
- 重複：同一次載入內連跑 3 次（不重新載入模型）
- 指令：
  ```

  taskset -c 0,1,6-11 ~/llama.cpp-pp/build-pp/bin/llama-pp-stage --role first -m ... -s 33 --next 192.168.137.31:9000 --ref /tmp/stage_ref_31b.bin \
  ```

  - 管線短對話：`pprep_first_1118_2204.*`、`pprep_last_1111_0752.*`
  - 管線長對話：`pp4kq8L_first_1118_2218.*`、`pp4kq8L_last_1111_0805.*`

## 解讀
1. **雜訊遠小於我們在比較的差距**。同一次載入內的變異約 0.05%，跨天的變異約 0.25%。所以之前的結論都不受雜訊影響：短對話「持平」（差 0.6–1.9%）、各自長對話「持平」（差 2–3%）、q8_0 讓 16 人長對話快 44%。
2. **因為變異這麼小，之後每個組態量 1 次就夠**；只有差距小於 1% 時才需要重複。跨天比較時，要注意可能有約 0.5% 的差異（可能是溫度或開機狀態，尚未查明）。
3. 同樣 32 人短對話，資料平行每板只剩 2.4 GB，管線前段還有 10.4 GB、後段 12.7 GB，和 `6.13` 長對話的情形一致：**吞吐持平時，管線還有大量記憶體可以再加人或加長上下文**。
4. 這些都是 3 次重複，只看得到「同一個載入狀態下」的穩定度。如果要證明跨開機的穩定度，需要在不同開機後各量一次（目前有 3 次 32x2，已涵蓋 2 次開機）。
